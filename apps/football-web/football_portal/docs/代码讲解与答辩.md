# 从 Python 基础到足球 Web 与 LLM 答辩

这份说明围绕你负责的 Web 和大模型部分。数据清洗、模型训练和精度评价由同学说明；你需要理解它们的输入输出，以便解释页面数字的来源。

## 先读懂 Python 的几个基础

| 写法 | 本项目中的意思 |
| --- | --- |
| `def normalize_frame(...):` | 定义一个可以反复调用的函数，集中检查每帧结果 |
| `return {...}` | 返回字典；字典用有名字的键保存结构化数据，如 `boxes` 和 `frame_index` |
| `frames = []` | 列表保存多帧数据；一帧的 `boxes` 也是列表，因为一张图可以有很多目标 |
| `for box in frame["boxes"]:` | 逐个检测框处理，避免只留下最高置信度目标 |
| `if label == "player":` | 只有球员才检查 A/B 属性，足球和裁判不参加球队统计 |
| `with path.open(...) as stream:` | 打开文件并在使用结束后自动关闭 |
| `try / except / finally` | 捕获可处理的错误；最终释放视频读取器、编码器和数据库连接 |
| `class AnalysisJob(models.Model):` | 定义数据库表的结构，不是定义 YOLO 模型 |
| `Path(...)` | 用路径对象组织文件，减少字符串拼接带来的错误 |
| `None` | 明确表示未知或没有值，例如空检测时 `best_conf` 为 `None`，不能写成虚构的 0 分准确率 |

Python 字典通过 JSON 序列化后发送给浏览器；浏览器用 JavaScript 读取同名字段并画图。JSONL 是一行一个 JSON 对象，适合逐帧结果；CSV 适合查看表格统计。这些格式负责交换数据，不负责判断模型是否正确。

## 一次点击究竟经过哪些代码

1. `manage_football.py` 选用新增的 `football_portal.project_settings`，不改原项目入口。
2. `project_urls.py` 把 `/football/` 交给新模块，同时保留原台账路由；`urls.py` 将具体 URL 对应到 `views.py` 的函数。
3. 浏览器的 `app.js` 用 `fetch` 上传文件及参数。`views.jobs_view` 检查格式、大小、数值和模型，再创建 `AnalysisJob`。
4. `jobs.submit_job` 将任务交给单工作线程队列。`jobs._run` 另启算法 Python 子进程运行 `bridge_worker.py`；Web 环境不必安装 PyTorch。
5. `bridge_worker._reader` 优先使用 ODPlatform FrameSource 逐帧读取，再按源帧号执行采样，保留真实源帧号、秒数和尺寸；导入不可用时使用兼容读取器并记录实际来源。
6. `YOLO.predict` 返回每个框的类别、置信度和原图坐标。`annotations.render_annotations` 根据真实框绘制角色颜色、简洁置信度标签与足球圆环，全部原始框写入 JSONL。圆环是显示辅助，不会扩大模型的实际框或改变统计。
7. `results.normalize_frame` 规范化每帧；`build_analysis` 从逐帧数据计算统计。Web 主进程再次读取结果并重新统计，页面读取同一份结果。可下载的结果 JSON 保存完整帧，数据库和轮询 API 则保留轻量结果。
8. 如果使用 LLM，`llm_service.build_context` 选取可解释字段，`answer` 组合提示词并调用外部接口；回答和用量写入本模块独立数据库。

这条调用链中的三个“模型”概念不同：Django Model 是数据库结构，YOLO Model 是目标检测网络，LLM Model 是语言生成模型。答辩时不能混为一谈。

## Django 在这里做什么

Django 的 Model、View、Template 可以分别理解为“数据结构”“请求处理”“页面模板”。`models.py` 存任务和助手记录，`views.py` 接收 HTTP 请求并组织调用，`templates/.../index.html` 提供页面骨架。`app.js` 接管页面切换、异步请求、足球局部放大和 SVG 图表；`home_hub.js`处理应用大厅、可拖动场景和球衣配色，`home_hub.css`提供草坪照片、App图标和深色视觉。背景是装饰素材，与真实YOLO结果分开。

`@require_POST` 限制接口的方法，`@ensure_csrf_cookie` 让页面获得 CSRF token。浏览器发送修改请求时带 `X-CSRFToken`，避免第三方页面随意替本机用户发起任务。

`owner_session` 把任务与当前浏览器会话关联；查询任务时同时筛选 ID 和会话，不是知道 UUID 就能读取别人的文件。当前是本机课程展示方案，没有实现多用户账号权限系统；清理浏览器 cookie 或换浏览器会得到新会话。

独立数据库让迁移、测试和演示产物不覆盖同学原数据库。新增设置从原设置继承必要的 Django 配置，再覆盖新模块的应用、路由和数据库，这是新增扩展，不需要编辑同学的 settings。

任务队列采用单进程中的 `ThreadPoolExecutor(max_workers=1)`，算法另启子进程，避免把耗时检测直接放在页面请求里。它适合本机演示，不提供服务异常中断后的自动续跑；任务状态被存进数据库，并不等于工作线程也持久化了。

## 四段需要重点会解释的代码

### 检查有限数值

`results._number` 先拒绝布尔值，再转换为浮点数并检查 `math.isfinite`。因为 Python 中 `bool` 也是整数的子类，仅判断“能不能转成数字”会把 `True` 当作 1；NaN 和 Infinity 也会污染统计和 JSON。

### 规范化坐标和类别

`normalize_frame` 检查四类名称、置信度范围和正面积框，再计算：

```python
cx = (x1 + x2) / 2
cy = (y1 + y2) / 2
w = x2 - x1
h = y2 - y1
```

`cx/cy` 是原图框中心，不是球场上的真实坐标。只有知道原图尺寸时，才能用 `cx / width` 和 `cy / height` 形成 0–1 的画面位置。归一化输入还必须显式声明坐标空间；不凭数值大小猜测。

数字类别必须有明确 `class_names`。同一编号在两个权重中可能对应不同类别，代码先按模型名称找到语义，再转换成本模块的规范编号。

### 从框数生成统计

`build_analysis` 对每帧逐个框计数：四类累计框数、每帧可见目标数、各类置信度分布、有足球检测的帧数。空检测帧仍参加分母。

例如两帧都检测到同一个球员，累计球员检测框是 2，不能说出现了 2 个不同的人。只有稳定跟踪 ID 才可能跨帧去重，而当前模块没有跟踪器。

### 组织安全的 LLM 上下文

`build_context` 采用白名单，只取模型标识、参数、统计及局限。`answer` 使用 report/diagnosis/chat 三种模板和系统约束，问题及历史有长度上限；请求中的 `temperature=0.2` 用于降低表达的随机性，不能保证回答事实正确。

API 密钥只出现在服务端请求头中，不发给页面、不放入提示词、不随原媒体上传。只有配置 `FOOTBALL_LLM_API_KEY` 才认为本项目 LLM 就绪，其他项目的环境变量不自动替代。发生读取超时后不自动重复生成，减少重复收费的可能；连接建立阶段的超时才做有限重试。

## 答辩问题与参考回答

1. **你和同学各做了什么？** 你负责 Django 页面、任务 API、结果展示和 LLM 接入；同学负责数据和 YOLO。新桥接读取同学权重及帧输入能力，没有改同学的原源码。
2. **为什么有两个仓库？** ODPlatform 承载算法基础流程；defect_manage 是 Django 应用。当前使用独立扩展把算法结果接入 Web。
3. **为什么没有用银行项目的 AUC、SHAP？** 本次任务是目标检测，输出框和类别，与银行分类特征及解释方法不同。只参考页面组织和使用流程。
4. **YOLO 与 LLM 谁在检测足球？** YOLO 根据像素输出框；LLM 根据结构化统计做文字解释。当前不把原图交给 LLM 判框。
5. **`conf=0.89` 是 89% 准确率吗？** 不是，它是模型对该预测的置信度。准确率、Precision、Recall 和 AP 需要真值标注与匹配规则。
6. **为什么不能只保留 `best_class`？** 足球画面通常有多个目标。最高置信度框不能表达完整场景，所以保留全部 `boxes` 和所有处理帧。
7. **步长为 2 会怎样？** 处理源帧 0、2、4 等，减少计算；源帧号和时间戳仍保留。统计只覆盖处理过的帧，不能假定未处理帧有同样结果。
8. **为什么有足球的帧比例不是召回率？** 分母是所有处理帧，不是人工标注的足球真值目标数；检出框也可能误检。
9. **位置分布为什么不叫跑动热力图？** 它是摄像机画面中的框中心，摄像机也会移动；没有场地标定和人员跟踪，不能对应真实跑动。
10. **图表的数据哪里来？** 从 JSONL 中每帧的真实框重新累计，并与 CSV 使用同样规则；不使用写死的示例点。
11. **没有密钥时怎么办？** 检测和统计仍可用；LLM 按钮提示未配置。本地摘要单独标记，不能称为真实大模型回答。
12. **为什么费用有时未知？** 服务商可能没返回完整 usage，或没配置实际单价；未知不能填 0，最终以服务商账单为准。
13. **为什么不让网页上传 `.pt`？** PyTorch 权重需要可信来源；本模块只从服务端配置目录加载同学确认的权重，并记录 SHA256。
14. **SHA256 能证明模型效果好吗？** 不能，只能标识文件内容并核对元信息是否对应。效果要看独立测试数据的评测。
15. **如何确认没有改同学代码？** 对原跟踪文件做 SHA256 核对，再检查 Git diff；本次提交候选仅包含新模块和新入口。
16. **测试通过是否等于整站正式联调完成？** 不等于。还要区分程序测试、真实图片/视频接口测试、同学最终权重验收和真实 LLM 服务验收。
