# 足球视觉分析门户：Web 与 LLM 模块

本模块负责你现在分工中的 **Web 页面、大模型解释与两者之间的数据衔接**。同学继续负责数据集、YOLO 训练、模型评价和正式权重。本模块不训练模型，也不修改两个仓库已有的源码、配置或文档。

页面以足球应用大厅作为入口：九个无编号App图标（含VAR复核与运行监控）、统一球场照片风格的三张场景卡，以及任务与数据运行摘要。进入应用后可返回大厅，或使用“切换应用”展开图标菜单；数据页采用深色半透明面板。整个Web由Django提供模板、接口、CSRF、会话和数据库，JavaScript负责交互。

标注图仅显示置信度，球员青色、门将紫色、裁判橙色；足球用亮黄色框、圆环和准星重点标记，并提供真实原图局部放大。详细类别保留在表格与 JSON 中。参见[界面改版说明](docs/界面改版说明.md)。

场景轮播默认9秒自动播放，可由`FOOTBALL_CAROUSEL_SECONDS`调整；支持箭头、圆点、拖动、触摸和键盘，以及显式暂停。悬停/交互/后台/离开总览时暂停，减少动态偏好下停播。“我的主场”已换成任务与数据摘要。球场背景为内置工具生成的装饰图，不是比赛数据；完整提示词及保存位置见[视觉素材说明](docs/视觉素材说明.md)。

## 安装与启动

以下命令都在 `defect_manage` 项目根目录执行。Web 使用独立 Python 3.12 或更新版本；YOLO 使用同学已经配置好的算法解释器，避免在 Web 安装过程中升级同学的 PyTorch 环境。

```powershell
# 先确保当前 python 是 Python 3.12 或更新版本。
.\football_portal\scripts\setup.ps1 -Python python
Copy-Item .\football_portal\.env.example .\football_portal\.env
```

在自己的编辑器中填写 `.env`。模型路径必须由同学提供并确认可信；浏览器不接受上传 `.pt`。相对路径以 `defect_manage` 项目根目录为起点。例如下面是目录结构示意，需要替换为实际位置：

```dotenv
FOOTBALL_MODEL_PATH=../ODPlatform/models/football/best.pt
FOOTBALL_MODEL_METADATA=../ODPlatform/models/football/model_metadata.json
FOOTBALL_MODEL_LABEL=同学确认的足球检测模型
FOOTBALL_PLATFORM_ROOT=../ODPlatform
FOOTBALL_INFERENCE_PYTHON=../ODPlatform/.venv/Scripts/python.exe
FOOTBALL_DEVICE=cpu
FOOTBALL_LLM_API_KEY=
```

使用 CUDA 时，将 `FOOTBALL_DEVICE` 改为算法环境支持的设备，如 `0`。元信息不存在时可留空，但页面会提示来源未完整核验。只想查看页面或导入 JSON 时，模型路径可暂时留空。

```powershell
.\football_portal\scripts\start.ps1
```

启动脚本会先迁移独立数据库，再启动本地开发服务。打开 [足球视觉分析门户](http://127.0.0.1:8502/football/)。这是本机课程展示入口，尚未部署为公网服务。原台账在同一服务的 `/defect/list/` 仍可访问，但使用本模块的独立数据库。

也可以使用已经安装 Web 依赖的解释器：

```powershell
.\football_portal\scripts\start.ps1 -Python .\football_portal\.venv\Scripts\python.exe
```

## 大模型配置与费用

只读取本项目的 `FOOTBALL_LLM_API_KEY`，不会自动读取银行项目的 `.env` 或借用 `DEEPSEEK_API_KEY`。密钥只在本机 `.env` 中填写，不需要发给其他人，不进入 Git。

默认使用兼容 OpenAI 请求格式的 DeepSeek 接口，模型名为 `deepseek-flash`；服务地址和模型均可通过 `.env` 调整。官方 DeepSeek 地址使用非思考模式，在受限输出长度内直接生成统计解读；其他兼容地址不发送这一专用参数，参见[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。是否有可用额度、实际价格和账单，以 [DeepSeek 官方定价说明](https://api-docs.deepseek.com/quick_start/pricing/) 及账户信息为准。调用外部接口可能产生费用，代码不写死单价。

当前交付尚未填写本项目密钥，**没有进行真实 LLM 付费调用**。无密钥时页面明确提示未配置；“本地统计解读”是 Python 规则生成，不伪装为大模型回答。用量缺失或未填写每百万 token 单价时，费用是未知，不能解释成免费。填写自己的密钥后重启服务，再进行一条小范围问答即可完成真实接口验收。

## 模型与统计的边界

- 默认检测四类：`ball`、`goalkeeper`、`player`、`referee`。真实推理会验证权重类别；不使用普通 COCO 权重冒充足球四类模型。
- `boxes` 保存全部预览帧检测框；`best_class`、`best_conf` 仅用于兼容原字段，不能替代多目标结果。
- 跨帧框数会重复计算同一个人，不是整场独立人数；有足球检测的帧比例不是召回率或控球率。
- 位置图展示画面内的框中心，不是球场坐标。当前没有跟踪、场地标定或战术事件模型，不能推出跑动距离、速度或真实控球率。
- LLM 接收经筛选的统计上下文，不上传原始图片或视频；没有标注真值时，不报告准确率、漏检率或战术结论。

本机已使用旧实验 C44 的 YOLOv8s/960 权重进行真实图片联调，页面显示 1 个足球、22 个球员、2 个裁判、0 个门将。这是模型输出示例，不能作为检测正确率或同学最终模型效果。视频接口也已真实调用 YOLO：用真实验证图片重复组成 12 帧测试短片，按步长 2 处理 6 帧，视频播放、JSONL/CSV/页面统计和完整结果再导入均通过。这段短片只验证接口，不是实际比赛录像。正式交付时应由同学确认权重及其测试报告，只需替换 `.env`，无需修改 Web 源码。
