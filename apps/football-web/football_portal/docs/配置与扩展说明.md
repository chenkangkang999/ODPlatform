# 配置驱动与模块扩展

本轮不把42种事件复制到页面、Python校验器和JavaScript中分别维护。新增文件仍全部位于自己的`football_portal/`，不改同学已有源码。

| 要修改的内容 | 唯一配置位置 / 入口 | 生效方式 |
| --- | --- | --- |
| 事件名称、code、分组、子类、证据要求、规则入口 | `data/event_taxonomy.json` | Django `/football/api/events/`读取；VAR选择器、证据提示、后台校验与监控共用。改后重启服务 |
| 数据来源、固定版本、比赛分组与抽样数量 | `data/event_download_plan.json` | 下载器`--plan`和`--groups`选择；已存在文件不重复下载 |
| 原始数据与派生预览图目录 | `.env`的`FOOTBALL_EVENT_DATA_DIR` | 默认模块`.local/datasets/football_events/`；改后重启，下载器用同一目录的`--output`参数 |
| 轮播速度 | `.env`的`FOOTBALL_CAROUSEL_SECONDS` | 默认9秒；Django渲染`data-interval-ms`，JS只读取这个值 |
| 监控刷新频率 | `.env`的`FOOTBALL_MONITOR_REFRESH_SECONDS` | 默认10秒；Django模板与监控API使用相同配置 |
| 已下载文件与数据覆盖 | 数据目录的`manifest.json` | 由下载器生成，含来源、字节数、SHA256、类型与事件关联；监控从文件读，数字不手填 |
| 四类检测权重、算法解释器、模型元信息 | 已有`FOOTBALL_MODEL_*`、`FOOTBALL_INFERENCE_PYTHON`配置 | 沿用已验收的检测接口；不在前端写绝对路径 |

相对配置路径以Django仓库根目录为起点。下载器默认与服务默认数据目录一致；自定义目录时，将`--output`设为`FOOTBALL_EVENT_DATA_DIR`解析后的同一位置。更新源码中的下载清单摘要不会让另一台机器自动拥有视频；原始文件存在与否以本地manifest核验为准。

## 监控面板的数据口径

任务、失败原因、人工复核和LLM记录仅统计当前浏览器会话；原始研究数据是项目本地共享目录。浏览器进入总览或监控时刷新，离开或切换后台后停止轮询。没有采集GPU温度、利用率和准确率，因此不显示模拟读数。

下载时计算SHA256，视频实际解码、预览图检查由下载工具完成；监控每次只核对路径、文件存在和字节数，明确不等于重新计算全部文件哈希。路径越界、重复条目、缺失文件、错误大小和下载失败分别显示，不把失败文件计入已下载数量。

“有视觉样本”仅说明清单里有相关视频或图片，不保证覆盖该事件的所有子类，也不说明标注正确。“仅结构化标注”不能用于训练YOLO图像模型。自动能力根据事件目录的`automated_available`显示；当前全部为false，不能只改成true就宣称验收通过，必须先接入模型、记录版本并完成真值评测。

## 与同学算法的边界

四类目标检测、事件分类、人工证据和LLM解释分别保留来源。`card`为历史红黄牌合并记录的兼容值，新记录按目录分别选择黄牌、红牌和两黄变一红。所有42项均可人工分类保存，不代表当前自动识别了42项。

现有四类检测器继续严格验证类别和坐标。若同学增加球门、场线或牌模型，需要新增对应模型schema与适配器，不能把新类别编号硬塞进旧四类映射，也不能仅修改页面文字假装接口完成。参考`42类事件与算法接入.md`中的候选事件契约；当前尚无自动事件导入API，LLM仍解释检测统计。

轮播的三张卡片共用球场照片样式。页面悬停、键盘操作、拖动、后台、离开总览时暂停；系统减少动态效果偏好下停止自动播放。用户可用播放/暂停按钮控制，手动切换一直可用。“我的主场”及其球衣偏好已移除，不影响真实检测的角色颜色。
