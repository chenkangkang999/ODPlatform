# 42类足球事件：数据口径、算法分工与接入约定

核验日期：2026-10-26。规则参考IFAB 2026/27，具体比赛以其采用的规则和赛事规程为准。

本清单完整保留用户提出的42项需求。它们并非42个YOLO物体类别：其中有物体与动作、时序事件、规则结论、时间统计、战术分析和环境标签。当前原四类YOLO只定位足球、球员、门将、裁判；新增的人工复核分类、已下载数据标签、已经训练并接入的事件模型，需要分别记录。`data/event_taxonomy.json`中的42个项目全部设为`model_status=untrained`、`automated_available=false`，不把页面选项当作已实现的自动识别。

事件名称、稳定代码、分组、子类、所需证据和适用的`rule_url`集中放在该JSON配置中；页面和接口读取配置，避免在JavaScript和Python分别维护42项硬编码映射。20项关联了已核验的IFAB规则入口；技术/战术/环境项目没有强行附上无关规则。配置中的模型状态必须随真实验收更新，不凭下载完成或菜单可点击自动升级。

## 同学截图中的四层方案如何调整

整体方向“检测—跟踪—规则—解释”可以作为框架，但不能直接采用截图里的几条简化判断。

| 截图中的思路 | 本项目采用的准确口径 |
| --- | --- |
| 比较最靠前防守球员与进攻球员的图像x坐标 | 越位位置要结合队友触球时刻、球、倒数第二名对手、进攻方向与合法身体部位；需处于同一几何坐标系，并进一步判断参与实际比赛和规则例外。镜头倾斜时原始x坐标不可比。越位位置本身不等于越位犯规。 |
| 球的中心点完全越过门线就判进球 | 应核对整个球体是否全部过线、位于门柱之间和横梁下；还要复核进球方之前的违规。普通转播视角及未校准参考线不能提供专业门线精度。 |
| 两个人框距离小且运动快就判冲撞犯规 | 可作为接触候选，不能直接判犯规。需要完整动作、触球顺序、接触部位、强度、影响及比赛语境；摄像机运动会干扰像素速度。 |
| 跟踪固定ID后就能说“7号球员” | 跟踪ID不是球衣号码。遮挡、出画和切镜会产生ID切换，需重识别、球队信息、球衣OCR或人工阵容映射，并允许身份未知。 |
| 裁判举牌后自动把牌记给附近某球员 | 牌物体检测、举牌动作、受牌人关联和处罚理由是不同任务。远近关系不足以确定受牌人；第二黄牌还需要同一人的历史纪律记录。 |
| 规则输出直接写“进球有效”“犯规确定” | 保留候选/证据缺失/人工核验状态。LLM只解释被允许读取的事实和证据，不把检测置信度改写成确定判罚。 |

越位依据见[IFAB Law 11](https://www.theifab.com/laws/latest/offside/)，整球越线和进球前违规依据见[IFAB Law 10](https://www.theifab.com/laws/latest/determining-the-outcome-of-a-match/)。接触与犯规认定需按[IFAB Law 12](https://www.theifab.com/laws/latest/fouls-and-misconduct/)结合具体情境。上述方案属于教学辅助分析，不具备官方VAR系统的授权或判罚地位。

当前[IFAB VAR协议](https://www.theifab.com/laws/latest/video-assistant-referee-var-protocol/)并非允许复核全部普通黄牌：2026/27包括明确错误的第二次警告导致罚下的情形，但不包括漏判的潜在第二黄牌；赛事可选角球纠错也应单独确认。页面记录42项事件，不意味着42项都属于正式VAR介入范围。

## 42项完整目标及证据要求

本表的“输入”是后续实现需要的证据，不表示当前已下载或标注齐全。实际文件、字节、SHA256和类别分布以本地下载`manifest.json`为准。一个事件可以有多个标签，例如“铲球＋冲撞犯规＋禁区内＋黄牌”；不能为了凑42个互斥类别而丢失关系。

| ID / code | 用户需求及子类 | 任务性质 | 最低证据与限制 |
| --- | --- | --- | --- |
| 1 `offside` | 越位 | 几何与规则 | 触球时刻、球与倒数第二对手、合法部位、参与比赛；允许证据不足。 |
| 2 `goal` | 进球：有效/无效 | 几何与规则 | 整球过线及进球前违规；Goal事件时间戳不能替代有效性标签。 |
| 3 `foul` | 冲撞犯规 | 时序动作与规则 | 正常对抗和犯规负样本、多视角、接触前后；框相近不是犯规。 |
| 4 `handball` | 手球 | 接触动作与规则 | 球/手臂接触、姿态和动作语境；碰手臂不一律构成犯规。 |
| 5 `yellow_card` | 黄牌 | 物体、动作与身份 | 黄色牌、出牌动作、受牌人及官方/人工确认。 |
| 6 `red_card` | 红牌 | 物体、动作与身份 | 红牌、受牌人、直接红牌或第二黄牌的记录。 |
| 7 `second_yellow_red` | 两黄变一红 | 历史关联与规则 | 同一人的两次警告和罚下序列，不能只看一张红牌。 |
| 8 `penalty` | 点球 | 事件与规则 | 犯规性质和位置、裁判决定、点球执行；接触不直接等于点球。 |
| 9 `free_kick` | 任意球：直接/间接 | 重启与规则 | 暂停/重启、犯规理由、裁判手势或官方标注；类型可未知。 |
| 10 `corner` | 角球 | 时序重启 | 底线出界、最后触球方、角旗区执行。 |
| 11 `throw_in` | 界外球 | 时序重启 | 整球越边线、最后触球方和掷球动作。 |
| 12 `goal_kick` | 球门球 | 时序重启 | 底线出界原因和球门区重启；门将起脚不一定是球门球。 |
| 13 `foul_location` | 禁区内/外犯规 | 事件位置属性 | 已核验犯规、实际接触/持续动作、标定与边界；框中心不是犯规点。 |
| 14 `shot` | 射门：射正/射偏/被封堵 | 时序球动作 | 触球后轨迹、球门几何、封堵/扑救/出界结果及统一统计定义。 |
| 15 `pass` | 传球：成功/失败 | 时序球动作 | 传出者、目标、后续接触和球队；需明确成功口径。 |
| 16 `dribble` | 带球/盘带 | 时序球动作 | 持球关联、连续移动和对手；过人与普通带球可分属性。 |
| 17 `tackle` | 抢断 | 球权转换动作 | 触球次序及前后球权，不等同铲球。 |
| 18 `save` | 扑救 | 门将球动作 | 射门、门将动作、触球与后续轨迹；门将类别不是扑救标签。 |
| 19 `header` | 头球 | 身体接触动作 | 头/球接触序列和轨迹，可附传球/射门/解围用途。 |
| 20 `slide_tackle` | 铲球 | 身体时序动作 | 躯干/腿部动作、触球/触人；动作与犯规结论分开。 |
| 21 `dive` | 假摔/跳水 | 时序动作与规则 | 多视角、接触因果及人工核验；倒地不能直接推断欺骗意图。 |
| 22 `holding_pushing` | 拉人/推人 | 身体时序动作 | 手臂、球衣接触、持续及影响，是否犯规另判。 |
| 23 `shot_block` | 堵枪眼/封堵射门 | 时序球动作 | 射门后防守人触球及轨迹改变，与扑救/解围分开。 |
| 24 `kick_off` | 中圈开球 | 比赛阶段与重启 | 中圈、球开始运动、半场/进球后阶段。 |
| 25 `substitution` | 换人 | 状态与身份 | 换人牌/字幕、入场和离场身份；ID切换不等于换人。 |
| 26 `injury_stoppage` | 受伤倒地/治疗暂停 | 比赛状态 | 倒地片段、暂停及医护/官方记录；不输出医学诊断。 |
| 27 `added_time_board` | 补时/第四官员举牌 | 物体动作与OCR | 官员、电子牌、可读分钟数、比赛阶段，避免混淆换人牌。 |
| 28 `period_end` | 中场休息/全场结束 | 比赛阶段 | 时钟、哨声/官方事件、阶段与后续；视频结束不等于比赛结束。 |
| 29 `var_check` | VAR介入/耳机检查 | 裁判时序动作 | 耳机动作、字幕/回看/官方记录；摸耳机不一定是VAR。 |
| 30 `play_state` | 暂停/恢复 | 比赛状态机 | 球在比赛中、哨声/信号、暂停与重启，不用低运动代替。 |
| 31 `attack_direction` | 进攻方向：左/右 | 跟踪与坐标 | 队伍、半场/球门归属、镜头变换，声明图像或球场坐标。 |
| 32 `possession` | 控球率 | 聚合统计 | 可靠持球状态、有效时间、缺失区间和分母；框数不是控球率。 |
| 33 `formation` | 阵型：4-4-2/4-3-3等 | 全队时空分析 | 全队视野、球队/角色、球场位置与时间窗；局部镜头不足时不输出。 |
| 34 `offside_trap` | 越位陷阱 | 战术时序 | 防线集体运动、触球时刻及定义；发生越位不等于有意造越位。 |
| 35 `defensive_line` | 防线前压/回撤 | 战术时序 | 后卫映射、标定后运动、方向、窗口；排除镜头运动。 |
| 36 `high_press` | 高位逼抢 | 战术时序 | 球权、区域、防守人与持球人关系、可复现压力指标定义。 |
| 37 `counter_attack` | 反击 | 战术时序 | 球权转换、推进速度/空间、参与人及时间窗。 |
| 38 `celebration` | 球员庆祝 | 身体/群体动作 | 连续庆祝动作和前序事件；庆祝不能证明进球有效。 |
| 39 `coach_instruction` | 教练场边指挥 | 身份与时序动作 | 技术区画面、教练身份、手势/指挥片段。 |
| 40 `crowd_incident` | 球迷骚乱/投掷物 | 人群场景时序 | 看台连续画面、物体轨迹及核验；密集/欢呼不等于骚乱。 |
| 41 `match_environment` | 雨天/雪天/夜场 | 场景多标签 | 真实天气与照明样本；雨天和夜场可以同时成立。 |
| 42 `smoke_pyrotechnics` | 烟花/烟雾 | 环境场景时序 | 连续烟花/烟雾画面和核验标签，视觉检测不推断来源或危险性。 |

## 数据来源如何分工

[SoccerNet Action Spotting](https://www.soccer-net.org/tasks/action-spotting)提供17类事件时间点，包括越位、进球、犯规、牌、点球、任意球、角球、界外球、射正/射偏、开球和换人等。它适合做事件检索和时间线；不直接提供精确触球帧、越位合法身体部位、整球过线三维真值或受牌人检测框。其类别表不包含球门球，不应把门将开球标签强行映射为球门球。

[SoccerNet MVFouls](https://www.soccer-net.org/tasks/multi-view-foul-recognition)提供多视角动作与犯规严重程度。动作包括铲抢、拉人、推人、对抗、假摔、高抬腿和肘击；严重程度包括无犯规、犯规不出牌、黄牌级别、红牌级别。严重程度是动作判定标签，不等于视频一定出现裁判举黄/红牌，也不能凭它确定受牌球员身份。

[SoccerNet Camera Calibration](https://www.soccer-net.org/tasks/camera-calibration)和[Game State Reconstruction](https://www.soccer-net.org/tasks/game-state-reconstruction)可补充场线几何、球场定位与身份等基础任务；不等于已经提供越位陷阱、高位逼抢或阵型的现成真值。

公开结构化事件记录可以帮助调试事件表、时间线、统计和LLM上下文，不能替代图像/视频训练。下载报告应分列“视觉样本数”和“事件标注数”；同一真实视频抽出的相邻帧不算独立比赛。牌图片、环境图片或小规模公开视频必须先核验标签与许可，再纳入训练。

40–42等长尾事件以及27、29的特定官员动作，目前没有在本项目中核验出足够且可直接训练的完整数据。需要使用有权使用的比赛录像补充人工标注，或另找许可清楚的专项数据。不能为了宣称覆盖42项而把普通网页、无标签视频和合成球场背景算成该类训练样本。

## 五个处理环节与双方边界

1. **定位输入**：同学训练目标/关键点/牌/场线等检测器；保留原四类模型，新增模型使用独立版本、类别表和数据指纹。球门、场线适合关键点/分割或几何模块，不强求全部变为矩形框。
2. **跟踪与标定**：同学输出轨迹ID、队伍、身份映射、球场坐标、可靠性和切镜/丢失状态。ID需有作用范围，不能承诺全场永不变化；未确认号码使用unknown。
3. **候选事件**：同学提供时序模型或可解释候选规则，输出事件起止时间、参与者、证据和模型版本。框距离阈值等启发式必须注明来源和误差，不能叫正式裁决。
4. **规则证据与人工复核**：我们的Django保存素材、关键帧、未校准参考线、事件分类和人工意见；需要真正的几何模型才能输出校准线。缺失证据时保持`needs_evidence/unknown`。
5. **讲解输出**：我们负责LLM和Web。LLM读取被允许的模型候选/核验记录、规则版本、时间和证据缺口，分别表达“画面观察”“候选事件”“人工核验”，不修改判罚字段。当前真实LLM尚未读取VAR证据，不把模板统计说明冒充视觉大模型识别。

下面是建议契约，示例值不表示模型已接入或完成训练。当前人工VAR报告继续使用`source=manual_review`、`automated_decision=false`；不能把导入人工记录改成模型输出。

```json
{
  "schema": "football.event-candidate.v1",
  "event_id": "candidate-unique-id",
  "taxonomy_code": "foul",
  "source": "model_candidate",
  "match_id": "provided-by-dataset-owner",
  "period": 1,
  "start_time": 12.4,
  "end_time": 15.0,
  "timebase": "source_media_seconds",
  "score": 0.73,
  "model_id": "event-model-version",
  "dataset_fingerprint": "provided-by-algorithm-owner",
  "actors": [
    {"track_id": "shot-03:17", "team": "unknown", "jersey_number": null}
  ],
  "attributes": {"location": "unknown", "severity": "unknown"},
  "evidence": [{"frame_index": 248, "media_time": 12.4}],
  "calibration": {"available": false, "coordinate_system": "image"},
  "decision_status": "pending_human_review",
  "limitations": ["example values only; not experimental results"]
}
```

来源时间轴、比赛时钟和半场相对时间应分别保存，不能简单把视频秒数当作比赛分钟数。录像含回放、广告、暂停和剪辑时尤其需要校准；一段事件的多个回放应关联同一事件，避免重复计数。模型分数只用于对应任务的排序或校准，不是“判罚正确概率”。

## 数据与模型验收

- **数据**：逐文件URL/许可、字节和SHA256；按比赛/原视频分组拆分，关联回放和增强来源；统计实际正负样本、子类、时间段与机位。照片、视频、事件JSON、跟踪数据分开报数。
- **动作/事件**：报告每类Precision/Recall/F1及定义明确的时间容差、事件mAP；动作严重程度用各类召回、混淆矩阵等，不能把四类检测mAP当事件准确率。
- **身份/轨迹**：报告身份切换、轨迹覆盖和遮挡/切镜表现；确认号码的准确率和unknown比例单列。
- **几何**：只有有标定/关键点真值时报告球场位置或线误差，传播触球帧和部位误差；普通转播图不能声称毫米级越位或门线判定。
- **统计/战术**：先定义分母、有效时间、视野覆盖、战术窗口和人工真值，再比较控球率、阵型或逼抢；证据不足时不输出数字。
- **外部比赛**：在方案冻结后按独立比赛测试，不把同场相邻帧/同事件回放分到不同集合；报告跨球队、天气、夜场及小球困难情况。

## 监控面板应该显示什么

本地Django应显示实际持久化的任务数、排队/运行/失败/取消状态、最近错误、处理进度与可用结果；VAR待证据/已人工复核数；实际下载文件、占用字节、校验结果；42项的“已有视觉样本”“仅事件标注”“待获取”“模型未训练”分开显示。只统计当前浏览器会话可见的任务与案例，避免泄漏他人数据。

没有接入采集器就不展示假GPU温度/显存/吞吐；未取得统计真值就不展示编造控球率、准确率或自动判罚成功率。公开本地数据清单不能返回真实密钥、绝对磁盘路径、会话标识或受限媒体直链。
