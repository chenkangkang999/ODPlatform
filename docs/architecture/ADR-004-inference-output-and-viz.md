# ADR-004：推理输出参数可配置；美化绘制当前为桩，默认路径退到原生绘制

| 项目 | 内容 |
|---|---|
| 状态 | ✅ Accepted |
| 决策日期 | 2026-10-24 |

## 背景

推理结果的落盘与可视化原先有这些写死的值：

- `LocalFileSink` 里写死 `"output.mp4"`、`"mp4v"`、兜底帧率 `30.0`；
- 流水线里写死的队列长度与各种超时（纯工程常量）；
- `visualization.BeautifyVisualizer` **是个桩**：`from_yolo_results()` 只打包标签
  （boxes / confidences 被丢掉），`draw()` 直接 `return image`。

第三条的后果最严重且最隐蔽：**默认（美化开启）跑出来的视频/图片没有任何检测框，
既不报错，审计里还写着 `"beautified": true`**。用户会以为模型没检测到东西，
而实际上统计里的检测数是正常的。

## 备选方案

- 方案 A：把美化绘制实现出来（画框 + 中文标签 + 配色），默认走美化
- 方案 B：删掉美化这条路径，统一用 ultralytics 原生 `plot()`（本决策的当前状态）
- 方案 C：保留桩，但在运行开头显式告警并回落到原生绘制（本决策）

## 决定

1. **输出参数可配置**：文件名、编码器（fourcc）、兜底帧率进
   `configs/runtime/infer_pipeline.yaml` 的 `output` 段，默认值集中在
   `inference/defaults.py`；选定的值写进审计快照（`pipeline.output`）。
   这样换 H.264 等编码器不用改代码。
2. **工程常量具名化**：队列长度、超时、HUD 绘制数值全部提为具名常量
   （`inference/defaults.py` 与 `overlay.py`），代码里不再出现裸数字。
3. **美化绘制维持"桩"状态，但不再静默**：默认（`--no-viz` 未给）时按方案 C 处理 ——
   桩存在的事实写进 README「已知问题」；要出图就用 `--no-viz` 走原生绘制，
   它已实测可用（框与置信度正常）。
   真正的美化实现留待有明确视觉规范时再做，届时由新 ADR 取代本节。

## 理由

1. 输出参数（尤其编码器）是**用户会真的想改**的东西：`mp4v` 又慢又大
   （11 分钟 1080p 视频约 296 MB），换 H.264 收益直接。
2. 具名常量让"这个 3 秒超时是什么意思、能不能调"变成可读问题，也是评审的前提。
3. 美化绘制牵涉视觉规范（配色、中文字体、标签映射），在需求明确前实现等于返工；
   但**保持静默是不可接受的** —— 所以必须显式记录并给出可用替代路径。

## 后果

- 正面：输出可配；代码里没有裸数字；"默认没有框"这件事在 README/手册/本 ADR 三处可见。
- 负面：默认路径（美化）目前不出图，使用者必须知道加 `--no-viz` —— 这是过渡期的负担。
- 中性：`PipelineConfig` 增加了 `output` 段，`infer_pipeline.yaml` 模板应同步（`odp-gen-config`）。

## 撤销条件

- 实现真正的 `BeautifyVisualizer`（含字体与配色规范）后，本篇第 3 条由新 ADR 取代；
- 若决定永远不用美化（方案 B），则删除该模块与相关配置项，并在此标注 Superseded。
